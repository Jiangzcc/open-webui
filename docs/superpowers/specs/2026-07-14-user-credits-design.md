# 用户积分与图像调用计费设计

- 日期：2026-07-14
- 状态：已完成交互式设计确认，待用户审阅书面规格
- 适用项目：基于 Open WebUI 的二次开发
- 第一阶段范围：通用积分底座 + 文生图/图生图实际计费

## 1. 背景与目标

当前应用已经具备文生图、图生图能力，图像请求可以来自图像页面、公共 API、用户 API Key、聊天中间件和内置图像工具。项目目前没有可复用的余额、积分、订单或支付系统；已有 token usage 属于分析统计，不能直接承担账务一致性、余额防透支和审计职责。

本功能需要建立通用积分账户与账本，并在第一阶段将所有经过本 Open WebUI 部署的文生图、图生图调用纳入统一计费。普通用户能够查看余额、预计消耗和最近一年的完整积分明细；管理员能够配置多维价格、查询永久流水，并为用户人工增加或扣减积分。

本设计同时遵守一项长期约束：项目需要持续跟随 Open WebUI 上游升级，因此不得修改上游原有数据库表，绝大多数实现必须位于独立扩展目录；只有现有扩展点不足且关系到计费正确性时，才允许在少数上游文件中保留薄桥接。

## 2. 已确认的产品决策

| 主题 | 决策 |
|---|---|
| 第一阶段充值 | 不接真实支付，不向普通用户显示充值按钮；管理员在后台人工加减积分 |
| 实际计费范围 | 底层通用化，第一阶段只实际接入文生图和图生图 |
| 价格表达 | 基础价乘多个声明式计费维度；多个维度可同时生效 |
| 图像计费维度 | 支持尺寸、分辨率、宽高比、质量、图片张数同时参与；第一阶段质量固定为 `default` |
| 视频范围 | 底层为视频时长等维度预留扩展能力，但第一阶段不接视频计费 |
| 扣费时点 | 本地校验通过后、调用供应商前原子扣费；之后失败不退款 |
| 部分成功 | 不按返回图片数退款；请求已扣费后不做自动补偿 |
| 初始积分 | 新老用户均为 `0`，账户可惰性创建 |
| 管理员调用 | 免积分，但必须留下免计费用量审计记录 |
| 未配置价目 | 普通用户禁止调用；管理员仍可免积分测试 |
| 报价展示 | 图像生成器工具栏、生成按钮旁实时显示预计积分 |
| 报价变更 | 提交时按最新价目重新计算并直接扣费，不锁价、不要求再次确认 |
| 积分精度 | 用户余额和最终扣费均为整数；精确十进制计算后向上取整，最低扣 `1` |
| 负数余额 | 禁止；普通消费和管理员扣减都不能让余额低于 `0` |
| 管理原因 | 固定原因列表；选择“其他”时补充说明必填 |
| 管理入口 | 独立“积分管理”页面 |
| 普通用户入口 | 左下角 `UserMenu` 内展示余额，点击打开明细弹窗 |
| 普通用户明细 | 显示全部余额变动；普通用户仅可查询本人最近一年 |
| 管理员明细 | 永久查询全部账本，包括已删除用户 |
| 账号删除 | 完整保留扩展账户、身份快照和历史流水，不匿名化、不级联删除 |
| 调用渠道 | 网页、公共 API、API Key、聊天中间件、内置工具统一计费 |
| 幂等 | 支持幂等键；同一请求重试不重复扣费或调用供应商，并返回原结果或原错误 |
| 价目历史 | 只保留当前价目；每笔消费保存完整计价快照 |
| 全局开关 | 不提供关闭计费的全局开关；普通用户图像调用始终执行计费 |
| 上游兼容 | 原表零修改、扩展优先、薄桥接、独立迁移链和升级守卫测试 |

## 3. 当前代码基础与设计约束

### 3.1 当前图像调用中心

当前后端的两个中心函数位于 `backend/open_webui/routers/images.py`：

- `image_generations()`：文生图供应商分发中心；
- `image_edits()`：图生图供应商分发中心。

它们不只被 HTTP 路由调用：

- `backend/open_webui/utils/middleware.py` 的聊天图像链路会直接调用；
- `backend/open_webui/tools/builtin.py` 的 `generate_image` 和 `edit_image` 也会直接调用。

因此只在前端或 HTTP 中间件中计费会产生可绕过路径。计费 guard 必须覆盖这两个中心函数，同时保留用户身份、实际模型和规范化参数。

### 3.2 当前前端接入点

- 用户菜单：`src/lib/components/layout/Sidebar/UserMenu.svelte`；当前插槽只负责菜单触发器，不提供菜单内容扩展注册机制。
- 图像生成器：`src/lib/components/images/Images.svelte`；当前模型、尺寸/比例、分辨率和张数位于底部悬浮输入框工具栏。
- 管理员布局：`src/routes/(app)/admin/+layout.svelte`；管理员顶部导航是显式链接，不支持动态扩展注册。
- SvelteKit 页面本身可通过新增 `src/routes/(app)/admin/credits/+page.svelte` 实现，无需修改既有管理员页面主体。

### 3.3 上游升级原则

不追求字面上的“零侵入”。零侵入无法同时保证：

1. 新路由在应用中可达；
2. UI 入口可发现；
3. 所有进程内图像调用都在供应商调用前完成计费。

本设计采用“扩展岛 + 薄桥接”：数据库完全加法式，业务核心完全新增；上游文件只承担注册、挂载或上下文透传。

### 4.1 后端扩展目录

建议集中在独立命名空间：

```text
backend/open_webui/extensions/credits/
├── models.py
├── schemas.py
├── errors.py
├── repository.py
├── accounts.py
├── ledger.py
├── pricing.py
├── usage.py
├── image_adapter.py
├── guard.py
├── router.py
├── registration.py
├── compat.py
└── migrations/
```

职责如下：

- `models.py`：只定义 `ext_*` 扩展表；
- `schemas.py`：普通用户和管理员 API DTO；
- `errors.py`：稳定领域错误码；
- `repository.py`：扩展表数据访问；
- `accounts.py`：账户惰性创建、原子加减和非负约束；
- `ledger.py`：只追加账本和分页查询；
- `pricing.py`：通用多维计价器；
- `usage.py`：幂等、调用状态和原结果复用；
- `image_adapter.py`：把当前 Open WebUI 图像请求转换为稳定的计费上下文；
- `guard.py`：提供窄接口，如 `quote()`、`charge_once()`、`mark_result()`；
- `router.py`：`/api/v1/credits` 用户与管理员 API；
- `registration.py`：扩展迁移、路由和恢复任务注册；
- `compat.py`：集中隔离上游 User、Request、图像配置和模型解析变化；
- `migrations/`：独立迁移链。

### 4.2 前端扩展目录

```text
src/lib/apis/credits/
src/lib/components/credits/
src/routes/(app)/admin/credits/
```

新增组件至少包括：

- `CreditMenuEntry`：用户菜单余额与明细入口；
- `CreditLedgerModal`：普通用户积分明细；
- `ImageCreditQuoteBadge`：图像工具栏预计积分；
- 管理员账户、流水、调账和价目编辑组件；
- 独立 API client、类型和本地化资源。

不把余额加入现有 `$user` store，也不修改登录响应；用户菜单打开时独立请求余额。

## 5. 数据模型

所有表使用 `ext_` 前缀，不修改 Open WebUI 原表，不在原 `User` ORM 上添加 relationship/backref。

### 5.1 `ext_credit_account`

保存当前整数余额，支持快速读取和条件扣减。

| 字段 | 类型/约束 | 含义 |
|---|---|---|
| `id` | UUID，主键 | 扩展账户 ID |
| `user_id` | 字符串，唯一，非空 | Open WebUI 用户 ID 的逻辑引用，不建立数据库外键 |
| `balance` | 大整数，非空，默认 `0`，检查约束 `>= 0` | 当前整数积分 |
| `user_name_snapshot` | 文本，可空 | 最近一次业务操作时的用户名快照 |
| `user_email_snapshot` | 文本，可空 | 最近一次业务操作时的邮箱快照 |
| `created_at` | 时间戳 | 创建时间 |
| `updated_at` | 时间戳 | 最后变更时间 |

规则：

- 每个用户最多一条账户记录；
- 账户惰性创建；不存在等价于余额 `0`；
- 用户第一次查看余额、被管理员调账或首次消费时创建；
- 用户删除后账户保留；
- 已删除用户只允许审计查询，不允许继续调账或消费。

### 5.2 `ext_credit_ledger`

每次余额变化只新增一条记录。服务层不提供修改或删除账本的 API，也不在正常业务中更新历史行。

| 字段组 | 主要字段 |
|---|---|
| 标识 | `id`、`account_id`、`user_id` |
| 金额 | 有符号整数 `amount`、`balance_before`、`balance_after` |
| 分类 | `entry_type`、`reason_code`、`note` |
| 用户快照 | 用户 ID、姓名、邮箱 |
| 操作者快照 | 管理员或系统的 ID、姓名、邮箱 |
| 业务关联 | `usage_id`、幂等键、关联流水 ID |
| 计价快照 | 完整 pricing snapshot JSON |
| 时间 | `created_at` |

不变量：

```text
balance_after = balance_before + amount
balance_after >= 0
```

账本类型至少包括：

- `admin_increase`；
- `admin_decrease`；
- `service_usage`；
- `manual_refund`；
- `system_adjustment`。

管理员固定原因：

- `offline_recharge`：线下充值；
- `promotion_gift`：活动赠送；
- `manual_refund`：人工退款；
- `accounting_correction`：账务纠错；
- `violation_deduction`：违规扣减；
- `other`：其他，补充说明必填。

管理员免计费调用不改变余额，因此不写零金额账本，而写入用量审计记录。

### 5.3 `ext_credit_price`

保存当前价目策略。唯一业务键为：

```text
(service_type, resource_id, action)
```

示例：

```text
image | fal-ai/nano-banana-pro      | text-to-image
image | fal-ai/nano-banana-pro/edit | image-to-image
video | vendor/video-model-x        | text-to-video  # 仅预留
```

| 字段 | 含义 |
|---|---|
| `id` | 价目 ID |
| `service_type` | `image`，未来可扩展 `video`、`chat` |
| `resource_id` | 实际模型 ID |
| `action` | `text-to-image`、`image-to-image` 等 |
| `base_price` | 精确十进制基础价 |
| `rules` | 经过 schema 校验的声明式多维规则 |
| `rule_schema_version` | 规则结构版本 |
| `enabled` | 普通用户是否可使用 |
| `updated_by_id` | 最后修改人逻辑 ID |
| `updated_by_snapshot` | 最后修改人身份快照 |
| `created_at` / `updated_at` | 时间戳 |

价目修改直接覆盖当前记录，不保存价目版本表；每笔用量和消费账本必须保存当时完整计价快照。

### 5.4 `ext_credit_usage`

描述一次服务调用、幂等状态和业务结果；第一阶段只有 `service_type=image`。

| 字段组 | 主要字段 |
|---|---|
| 标识 | `id` |
| 业务定位 | `service_type`、`resource_id`、`action`、`channel` |
| 身份 | `user_id` 及用户身份快照 |
| 幂等 | `idempotency_key`、`request_hash` |
| 请求摘要 | 规范化计费上下文，不含 base64 原文 |
| 扣费 | `charged_credits`、`ledger_id`、完整计价快照 |
| 管理员免计费 | `exempt=true`、`charged_credits=0`、`ledger_id=null` |
| 状态 | `debited`、`invoking`、`succeeded`、`failed`、`unknown` |
| 结果 | 有限图片 URL 列表或脱敏错误摘要 |
| 时间 | 创建、开始调用、完成时间 |

唯一约束：

```text
(user_id, idempotency_key)
```

同一键对应不同 `request_hash` 时返回冲突；同一键同一请求不重复扣费、不重复调用供应商。

### 5.5 索引与关系

- `ext_credit_account.user_id` 唯一；
- `ext_credit_price(service_type, resource_id, action)` 唯一；
- `ext_credit_usage(user_id, idempotency_key)` 唯一；
- 账本索引 `(user_id, created_at)`；
- 全局流水索引 `created_at`、`entry_type`、`reason_code`；
- 用量索引 `service_type`、`resource_id`、`action`、`status`、`created_at`；
- 扩展表之间可以建立外键；任何指向 Open WebUI 原表的关系只保存逻辑 ID，不建立数据库外键。

## 6. 通用多维计价器

### 6.1 公式

```text
raw_price = base_price × 每个适用维度产生的 multiplier
charged_credits = max(1, ceil(raw_price))
```

第一阶段一次图像请求可以同时计算：

```text
基础价
× 尺寸倍率
× 分辨率倍率
× 宽高比倍率
× 质量倍率
× 图片张数
```

不将尺寸、分辨率和宽高比设计成三选一。管理员可以让多个维度同时参与；明确不影响价格的维度应显式配置为 `1.0` 或不加入该策略。

全程使用精确 `Decimal` 运算，不使用二进制浮点数。JSON 中倍率以十进制字符串保存，例如 `"1.25"`。

### 6.2 受控规则类型

不允许管理员编写任意代码、表达式或脚本。核心计价器只支持后端注册过的声明式类型。

#### `exact_map`

离散值映射，适用于尺寸、分辨率、宽高比、质量、是否含音频。

```json
{
  "key": "resolution",
  "kind": "exact_map",
  "values": {
    "1K": "1.0",
    "2K": "1.5",
    "4K": "2.5"
  }
}
```

#### `numeric_tier`

数值区间映射，未来适用于视频时长、帧率等。

```json
{
  "key": "duration_seconds",
  "kind": "numeric_tier",
  "tiers": [
    { "max": 5, "multiplier": "1.0" },
    { "max": 10, "multiplier": "1.8" },
    { "max": 30, "multiplier": "4.5" }
  ]
}
```

#### `unit_blocks`

按单位块向上计数，例如未来“每 5 秒为一个计费单位”。

#### `quantity`

正整数直接成为数量系数；第一阶段用于 `image_count`。

### 6.3 服务适配器与维度注册

通用计价器不直接读取供应商原始请求：

```text
原始请求 → 服务适配器 → 规范化计费上下文 → 通用计价器
```

第一阶段图像适配器注册：

- `size`；
- `resolution`；
- `aspect_ratio`；
- `quality`；
- `image_count`。

第一阶段 UI 不新增质量控件；适配器规范化为 `quality=default`。未来可以在不迁移账户和账本的前提下增加质量档位。

未来视频适配器可以注册：

- `duration_seconds`；
- `resolution`；
- `aspect_ratio`；
- `fps`；
- `audio`；
- `video_count`。

视频实际计费不属于第一阶段。

### 6.4 严格校验与 fail closed

- 管理员只能选择当前适配器注册的维度；
- 倍率必须为有上限的正十进制数；
- 拒绝 `NaN`、无穷大、零、负数和超长精度；
- `numeric_tier` 区间必须排序且不重叠；
- 一个参与计费的离散维度必须覆盖支持值或显式提供 `default`；
- 请求值无法匹配时返回 `price_rule_incomplete`；
- 未配置或未启用价目时返回 `price_not_configured`；
- 两种情况都不扣费、不调用供应商。

### 6.5 计价快照

每笔收费固化实际计算过程：

```json
{
  "service_type": "image",
  "resource_id": "fal-ai/nano-banana-pro",
  "action": "text-to-image",
  "base_price": "10",
  "factors": [
    { "key": "size", "value": "1536x1024", "multiplier": "1.3" },
    { "key": "resolution", "value": "2K", "multiplier": "1.5" },
    { "key": "aspect_ratio", "value": "16:9", "multiplier": "1.2" },
    { "key": "quality", "value": "default", "multiplier": "1.0" },
    { "key": "image_count", "value": 2, "multiplier": "2" }
  ],
  "raw_price": "46.80",
  "rounding": "ceiling",
  "charged_credits": 47
}
```

## 7. API 设计

统一前缀：`/api/v1/credits`。

### 7.1 普通用户接口

```text
GET  /api/v1/credits/me
POST /api/v1/credits/quotes/image
GET  /api/v1/credits/me/ledger
```

#### `GET /me`

- 使用现有 `get_verified_user`；
- 返回当前整数余额；账户不存在时返回 `0`；
- 用户菜单展开时懒加载；
- 不改变登录响应和 `$user` store。

#### `POST /quotes/image`

接收与图像请求相同的计费相关参数，由服务端解析实际模型并规范化。返回：

- 预计积分；
- 当前余额；
- 是否足够；
- 是否管理员免计费；
- 模型是否已配置；
- 逐维度计算明细；
- 结构化不可用原因。

报价不持久化、不锁价，也不是扣费凭据。最终提交时必须按最新价目重新计算。

#### `GET /me/ledger`

- 只允许查询本人；
- 强制限制到最近一年；
- 默认每页 `20` 条，服务端限制最大页大小；
- 支持全部、收入、消费、调整和日期筛选；
- 客户端不能通过修改日期读取一年以前的数据。

### 7.2 管理员接口

```text
GET    /api/v1/credits/admin/accounts
POST   /api/v1/credits/admin/accounts/{user_id}/adjustments
GET    /api/v1/credits/admin/ledger
GET    /api/v1/credits/admin/prices
POST   /api/v1/credits/admin/prices
PUT    /api/v1/credits/admin/prices/{price_id}
DELETE /api/v1/credits/admin/prices/{price_id}
GET    /api/v1/credits/admin/dimensions/{service_type}
```

所有接口使用现有 `get_admin_user`。

- 账户列表组合现有用户查询和扩展账户；没有账户的用户显示 `0`；
- 调账只接收正整数数额、方向、固定原因和可选说明；
- 管理员扣减不能让余额低于 `0`；
- 目标用户必须当前存在；已删除用户只读；
- 管理员永久查询全部流水；
- 价目 API 执行完整规则校验；
- 删除价目只删除当前配置，不影响历史用量和账本快照；
- 维度接口返回当前服务已注册维度和规则类型，用于受控表单。

## 9. 扣费、并发和幂等数据流

### 9.1 计费 guard

计费 guard 覆盖 `image_generations()` 和 `image_edits()`。它必须在兼容适配器解析实际模型和规范化计费参数后、第一次供应商 I/O 前完成扣费。

原 OpenAI、Gemini、fal、ComfyUI、Automatic1111 等供应商分支不重写。兼容适配器集中复用或映射当前模型解析规则；契约测试确保报价使用的实际模型与供应商分发一致。

流程：

```text
进入图像中心函数
  → 验证用户、权限和参数
  → 解析实际模型、action、channel 和计费维度
  → 查询最新价目并重新计价
  → 处理幂等记录
  → 管理员写 0 积分免计费用量
    或普通用户执行原子扣费事务
  → 事务提交
  → 调用原供应商逻辑
  → 更新用量状态与有限结果摘要
```

无用户身份的内部调用 fail closed；不能以匿名或系统默认身份免费使用供应商。

### 9.2 原子扣费事务

普通用户收费事务同时完成：

1. 惰性创建或获取账户；
2. 用条件更新扣减余额：只有 `balance >= charged_credits` 才能成功；
3. 追加负数账本；
4. 创建 `debited` 用量记录；
5. 提交。

任何一步失败则全部回滚。不能采用“先查询余额、再普通更新”的竞态方案。

余额不足时：

- 返回 `insufficient_credits`，包括所需和当前积分；
- 不写扣费账本；
- 不创建成功消费；
- 供应商调用次数为 `0`。

SQLite 和 PostgreSQL 均需验证条件更新和并发行为。

### 9.3 扣费边界

准确边界：

```text
本地身份、权限、参数、价目和余额校验通过
→ 扣费事务提交
→ 调用供应商
```

一旦扣费事务提交：

- 上游连接失败、超时或报错不退款；
- 少返回图片或无图片不退款；
- 进程崩溃不自动退款；
- 不自动重试供应商；
- 管理员如需补偿，必须另做一笔“人工退款”正向流水；
- 原消费流水永不修改。

### 9.4 幂等键来源

#### 图像网页和公共 API

- 每次用户主动点击生成创建新 UUID；
- 通过 `Idempotency-Key` 请求头传入；
- 自动网络重试复用同一个键；
- 用户再次主动点击创建新键，因此允许连续生成相同参数；
- 外部 API 客户端主动传键才能获得跨重试保证；不传时服务端为本次请求生成新键。

#### 聊天中间件和内置工具

使用稳定业务上下文生成或透传：

```text
user_id + chat_id + message_id + action + call_instance_id
```

- 聊天中间件已有 `chat_id`、`message_id` 元数据；
- 内置工具薄桥接透传已有聊天/消息上下文和可用的调用实例标识；
- 同一消息内多次调用必须通过 `call_instance_id` 区分；
- 缺少稳定上下文时生成新键并记录“不具备跨调用重试保证”，但仍正常计费。

### 9.5 请求哈希

`request_hash` 至少覆盖：

- 用户；
- 提示词哈希；
- 实际模型；
- action；
- 规范化计费上下文；
- 参考图片内容哈希。

不得把 base64 图片、提示词全文或视频原文复制进用量、账本或日志。

### 9.6 幂等命中

- 不存在：创建用量并继续；
- 相同键、不同哈希：返回 `409 idempotency_key_conflict`；
- `debited` / `invoking`：返回结构化处理中状态；
- `succeeded`：返回原图片 URL 结果；
- `failed` / `unknown`：返回原脱敏错误摘要；
- 所有命中路径均不再次扣费、不再次调用供应商。

### 9.7 外部调用状态

```text
debited → invoking → succeeded
                   └→ failed
          └────────→ unknown
```

- `debited`：扣费已提交；
- `invoking`：即将或正在访问供应商；
- `succeeded`：供应商成功且结果摘要已保存；
- `failed`：捕获到明确失败；
- `unknown`：进程中断后无法确认供应商是否收到请求。

数据库与外部供应商之间没有分布式事务，无法保证供应商 exactly-once。系统只能强保证财务幂等和“不自动再次调用”。恢复任务把超时记录标为 `unknown`，不退款、不自动重试。

## 11. 错误处理

| 错误码 | HTTP 状态 | 处理 |
|---|---:|---|
| `price_not_configured` | 409 | 模型暂不可用，不扣费、不调用供应商 |
| `price_rule_incomplete` | 409 | 参数无匹配倍率，阻止调用 |
| `insufficient_credits` | 402 | 返回所需和当前积分，不写扣费流水 |
| `idempotency_key_conflict` | 409 | 同键不同请求，拒绝 |
| `usage_processing` | 202 | 原请求处理中，不重复执行 |
| `credit_account_conflict` | 409 | 并发调账冲突，刷新后重试 |
| `invalid_adjustment` | 422 | 调账输入无效 |
| `credit_service_unavailable` | 503 | fail closed，供应商调用为 `0` |
| `provider_failed` | 400/502 | 已扣费，返回脱敏错误和消费流水 ID |

错误响应使用稳定错误码和结构化字段；前端按错误码本地化，不解析后端文案。

供应商错误脱敏要求：

- 不返回 API Key、Authorization Header 或内部请求头；
- 不返回数据库错误、堆栈和本地路径；
- 错误摘要限制长度；
- 服务端日志保留必要上下文，但同样不得记录密钥、提示词全文和图片原文。

## 12. 安全、权限与审计

### 12.1 身份与权限

- 普通用户接口使用 `get_verified_user`；
- 管理员接口使用 `get_admin_user`；
- 用户流水身份永远来自认证上下文；
- 目标用户 ID 只允许管理员调账接口使用；
- 用户 API Key 与网页 token 进入相同计费逻辑；
- 无身份内部调用 fail closed；
- 直接绕过 Open WebUI 调用供应商不属于本系统可计费范围。

### 12.2 输入验证与防滥用

- 调账数额为正整数；
- 余额由应用校验和数据库约束共同保证非负；
- 模型 ID、维度名、枚举值、备注、分页和日期范围均限制长度/范围；
- `Idempotency-Key` 限制格式和长度；
- 报价接口按用户限流，并对短时间相同规范化参数使用缓存；
- 明细接口固定最大页大小；
- 管理员调账接口使用更严格限流；
- 不提供修改或删除账本 API；
- 规则类型采用白名单，不执行任意表达式。

### 12.3 管理员审计

每次调账记录：

- 管理员 ID、姓名、邮箱快照；
- 目标用户 ID、姓名、邮箱快照；
- 变动前后余额；
- 增减数额；
- 固定原因和补充说明；
- 请求时间、来源和账本 ID。

价目变更通过 Open WebUI 现有事件/审计能力发布不含敏感数据的事件；历史扣费依据保存在用量和账本快照。

### 12.4 故障原则

不提供计费关闭开关，因此：

- 扩展迁移失败时应用启动失败；
- 运行期积分存储或计价器不可用时，普通用户和管理员图像调用均被阻止；
- 管理员虽免积分，但不能在审计不可用时调用供应商；
- 报价不可用时前端禁用生成；
- 非图像功能不应被单次普通计费请求故障影响。

## 13. 独立迁移与部署

### 13.1 独立迁移链

建议：

```text
目录：backend/open_webui/extensions/credits/migrations/
版本表：ext_credit_schema_version
业务表：ext_credit_*
```

- 只创建或演进 `ext_*` 表；

```text
→ 校验表和关键约束
```

1. 测试环境执行迁移和全部测试；

## 15. 可观测性与一致性检查

```text
ext_credit_account.balance
```

不一致时：

- 报警并阻止该账户继续消费；

- 保留修复证据和操作记录。

## 16. 测试策略

### 16.1 单元测试

- 多个维度同时相乘；
- `exact_map`、`numeric_tier`、`unit_blocks`、`quantity`；

SQLite 和 PostgreSQL 都要覆盖：

- 两个并发请求不能透支；
- 并发惰性创建只产生一个账户；
- 同一幂等键并发只产生一条负流水；

### 16.3 后端集成测试

- 余额不足时供应商 Mock 调用 `0` 次；
- 价目缺失或不完整时供应商调用 `0` 次；
- 扣费事务提交后才调用供应商；
- 供应商失败仍只有一笔扣费；
- 管理员扣 `0` 分但存在免计费用量；
- 幂等成功、失败、处理中、未知和冲突响应；
- 普通用户不能查询他人或一年以前流水；
- 非管理员不能查全局流水、调账或改价。

### 16.4 前端测试

- 用户菜单懒加载余额，不污染 `$user` store；
- 明细筛选、分页、最近一年边界和空状态；
- 报价防抖和旧响应竞态；
- 加载、余额不足、价目缺失、报价失败、管理员免计费状态；
- 生成按钮启用/禁用；
- 自动重试复用幂等键，主动再次点击使用新键；
- 管理员可配置多个同时生效维度；
- 调账确认、固定原因和“其他”必填。

### 16.5 E2E

1. 管理员配置价目；
2. 管理员给用户增加积分；
3. 用户看到余额和实时预计积分；
4. 用户生成图像，余额和流水同步变化；
5. 余额不足时阻止供应商调用；
6. 供应商失败仍显示扣费记录；
7. 管理员执行人工退款并产生新流水。

### 16.6 上游升级守卫

- 积分路由仍已注册；
- 两个图像中心函数仍经过计费 guard；
- 网页、API、聊天中间件和内置工具没有绕过路径；
- `UserMenu`、报价徽标和管理员导航仍挂载；
- 独立迁移只修改 `ext_*` 表；
- 新供应商或新渠道必须通过计费契约测试。

新扩展代码覆盖率不低于 `80%`；计价、原子扣费、幂等和权限分支要求接近完整覆盖。

## 17. 本期范围

### 17.1 包含

- 独立积分账户和永久追加式账本；
- 普通用户最近一年完整明细；
- 管理员独立积分管理页；
- 固定原因的人工加减积分；
- 通用多维声明式计价器；
- 图像多维实时报价；
- 文生图、图生图所有受控渠道统一扣费；
- 管理员免计费审计；
- 调用前原子扣费、失败不退款；
- 幂等、防并发透支和崩溃状态；
- 独立迁移链、桥接清单和升级守卫；
- 为视频时长等维度预留适配器能力。

### 17.2 不包含

- 微信、支付宝、Stripe 等在线支付；
- 普通用户充值按钮或充值申请；
- 聊天模型按 token 实际扣费；
- 视频模型实际扣费；
- 套餐、月度额度、优惠券和积分过期；
- 负数余额、透支和信用额度；
- 用户之间转账；
- 自动退款；
- 价目版本历史或短期锁价；
- 任意脚本/公式计价；
- 修改或删除历史账本；
- 对直接绕过 Open WebUI 的供应商调用计费；
- 为本功能提前建设通用插件框架。

## 18. 验收标准

1. 不修改任何 Open WebUI 原数据库表。
2. 绝大多数实现位于独立扩展目录，上游改动只限桥接清单。
3. 新老普通用户初始余额均为 `0`，余额永不为负。
4. 多个计费维度可以同时生效，使用十进制计算并向上取整。
5. 图像页面实时显示服务端预计积分。
6. 未配置价目、规则不完整、余额不足或积分服务异常时，供应商调用为 `0`。
7. 网页、公共 API、API Key、聊天中间件和内置工具不能绕过扣费。
8. 并发请求不能透支；相同幂等键不能重复扣费或重复调用。
9. 供应商失败、少返回图片或进程中断不自动退款。
10. 普通用户只能查询本人最近一年流水；管理员可永久查询全部流水。
11. 删除用户后，扩展账户、完整身份快照和账本仍保留。
12. 管理员调用扣 `0` 分，但留下免计费用量记录。
13. SQLite 和 PostgreSQL 的迁移、事务和并发测试通过。
14. 新扩展代码覆盖率至少 `80%`，核心财务和权限分支接近完整覆盖。
15. 上游升级守卫能发现路由、图像调用或 UI 桥接丢失。

## 19. 关键风险与缓解

| 风险 | 缓解 |
|---|---|
| 扣费后进程崩溃、供应商状态未知 | `unknown` 状态；不自动重试或退款；人工审计补偿 |
| 上游新增调用路径绕过计费 | 中心 guard、静态依赖检查、所有渠道契约测试、升级清单 |
| 价目误配置导致漏计费 | 受控维度、完整 schema、fail closed、普通用户禁用未配置模型 |
| 并发透支 | 数据库条件更新、同事务账本和用量、双数据库并发测试 |
| 网络重试重复收费 | 用户级幂等键、请求哈希、原结果复用 |
| 账本与余额不一致 | 不变量、事务、周期性重算、发现后阻止消费并受控纠正 |
| 上游升级冲突 | 扩展岛、薄桥接、不格式化上游文件、patch manifest |
| 删除用户后保存个人信息产生合规风险 | 这是已确认的业务决策；部署方必须确认隐私与数据保留政策允许完整保留 |
| 规则过度通用形成执行风险 | 仅声明式白名单类型，不支持任意公式或脚本 |
