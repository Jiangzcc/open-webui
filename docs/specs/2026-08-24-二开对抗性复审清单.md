## 一、冻结结论

### P0/P1：正确性、计费与安全

- [x] **R01 视频提交幂等不是原子的，也不耐目录变化。**
  - `backend/open_webui/extensions/videos/queries.py:create_video_task` 在 INSERT 前查询；
    并发 INSERT 冲突后直接返回赢家，没有再次执行
    `video_task_matches_submission`。同一用户、同一键、不同载荷可静默复用别人的赢家请求。
  - `backend/open_webui/extensions/videos/router.py:submit_video_task` 在查找旧任务前先检查当前模型是否启用；
    模型后来禁用时，完全相同的安全重试也会被 503 拒绝。
  - `backend/open_webui/extensions/videos/queries.py:video_task_matches_submission` 依赖重新构造当前目录参数；
    目录默认值或字段变化会把原请求误判为冲突。
  - 验收：持久化不可变的规范提交指纹；并发赢家二次比对；旧任务重放不依赖当前模型状态或目录。

- [x] **R02 图片/视频任务在调度失败后会留下永久 queued 僵尸记录。**
  - `backend/open_webui/extensions/creations/router.py:submit_image_generation_task`
  - `backend/open_webui/extensions/videos/router.py:submit_video_task`
  - 两条路径都先提交 queued 行，再调用进程内 scheduler；scheduler 抛错时只释放并发槽并返回错误，
    已提交行仍阻止后续幂等重试。
  - 验收：调度失败必须把任务原子/幂等地置为 failed（或安全删除未启动行），并发布终态事件。

- [x] **R03 供应商“未受理、已受理、状态未知”没有统一状态机，可能错退或错扣积分。**
  - `backend/open_webui/extensions/videos/service.py:run_video_task` 对已提交但不可重试的
    `VideoExecutionError` 会进入失败结算，并可能自动退回预扣；FAL 已受理/可能计费后不得猜测性退款。
  - `backend/open_webui/extensions/credits/image_billing.py:_invoke_image_provider` 则把所有普通
    `provider_failed` 都当成已扣费；FAL 明确在 POST 受理前失败时也不退回。
  - `docs/superpowers/specs/2026-07-14-user-credits-design.md` 的旧规则把所有 provider failure 合并，
    已不能表达真实的供应商受理边界。
  - `[x] backend/open_webui/extensions/credits/service.py:mark_usage_failed` 已实现原子恢复预扣，
    调用方按供应商受理边界分类，并由回归测试覆盖。
  - 验收：明确未受理才恢复；已受理或不确定时保留并进入恢复/对账；流水文案不能伪称供应商退款。

- [x] **R04 视频恢复依赖可变目录，且供应商恢复证据存在跨库丢失窗口。**
  - `backend/open_webui/extensions/videos/service.py:recover_video_task` 用当前目录重建 provider payload；
    模型删除、重命名、默认值变化后，已付费任务无法恢复。
  - 任务库的 best-effort 回调和 Provider Ops 记录分属两个事务；进程可能死在 Provider Ops 已提交、
    任务恢复字段尚未写入之间。
  - `[x] provider_ops/models.py`、迁移、`provider_ops/service.py:load_provider_recovery_state`
    已实现 video-only fallback，并修正测试夹具为合法视频记录。
  - 验收：任务持久化不可变执行快照；Provider Ops fallback 只读取合法视频记录；任务侧成功回填；
    已受理任务不发起第二次 POST。

- [x] **R05 图片任务没有已受理 FAL 的持久恢复链。**
  - `backend/open_webui/extensions/credits/image_billing.py` 在 `CancelledError` 时保留 invoking usage；
    `backend/open_webui/extensions/creations/generation_tasks.py` 在启动时却统一失败化未完成任务。
  - 图片任务未持久化 provider request/status/response URL、不可变 provider payload 或捕获阶段，
    重启后既不能安全 resume，又不能确认是否应退款。
  - 验收：持久化已受理证据和执行快照；重启仅 resume，绝不重复 POST；无法判断时进入 unknown/对账而非伪失败。

- [x] **R06 结果文件存在多处部分成功泄漏和重复交付窗口。**
  - `backend/open_webui/extensions/creations/capture.py:capture_reference_snapshots`：多参考图顺序上传，
    后一个失败时前面的 file 成为孤儿；调用方降级为无参考图后无法再清理。
  - `backend/open_webui/routers/images.py:_run_fal_image_pipeline`：多输出顺序落盘，后一个失败不清理前面的结果。
  - `backend/open_webui/extensions/videos/delivery.py:_finalize_mock_video` 与
    `_finalize_clip_mock_video`：视频成功、海报/数据库失败时不清理已上传 file。
  - `backend/open_webui/extensions/videos/service.py`：上游 file 上传完成到 creation/usage 终态提交之间崩溃，
    恢复会再次上传，缺少 task_id 元数据/可复用 delivery 记录。
  - 验收：所有多阶段落盘使用补偿清理；任务元数据可定位和复用已上传结果；清理失败可观测。

- [x] **R07 空供应商结果可被记为成功并收费。**
  - `backend/open_webui/routers/images.py:_run_fal_image_pipeline` 可返回空图片列表；
    `credits/image_billing.py:_finalize_image_success` 仍可把 usage 置 succeeded。
  - 验收：没有至少一个可用结果时不得进入 succeeded；按 R03 的受理状态进入失败或对账。

- [x] **R08 终态写入和异步事件有失败覆盖成功、丢失最新状态的问题。**
  - `backend/open_webui/extensions/creations/generation_tasks.py:run_image_generation_task`：作品与计费已成功后，
    task succeeded 写入失败会落入通用异常并把任务改成 failed；`CancelledError` 分支已有成功反查，普通异常没有。
  - `backend/open_webui/extensions/creations/events.py:publish_generation_event`：注释声称队列满时丢最旧保最新，
    实现实际丢弃新事件；终态可能延迟到 10 秒轮询才显现。
  - 验收：先从持久作品反查再判失败；事件队列满时合并/替换旧状态并保留最新终态。

- [x] **R09 发现页可见性和写操作存在并发竞态。**
  - `backend/open_webui/extensions/creations/discovery_service.py:_visible_posts_stmt` 未统一过滤被禁用分类；
    列表隐藏后，详情/content/poster 直链仍可读取。
  - `publish_creation` 并发发布同一作品时唯一约束败者返回 500，而发布其实已成功。
  - `set_reaction` 的先查后增删在并发 like/unlike 下可返回与最终数据库相反的状态。
  - 验收：所有公开读取共享同一可见性谓词；发布和 reaction 采用数据库原子语句并回读真实终态。

- [x] **R10 管理写入的并发/输入错误会泄漏为 500。**

  - `backend/open_webui/extensions/model_ops/service.py` 首次并发 upsert 可由唯一约束冲突产生 500。
  - 验收：导入前完整验证引用；并发 upsert 使用原子数据库语义或冲突后回读。
