# 图片页主模型映射与 Composer 布局优化设计

**日期：** 2026-07-26

**状态：** 待用户审阅

**范围：** `src/lib/components/images/Images.svelte`、`src/lib/utils/image-generation.ts`、对应测试与中英文 i18n

## 1. 目标

简化图片页的模型选择和文生图/图生图模式心智：用户只选择一个文生图主模型，前端依据参考图是否存在，自动使用该主模型或其一一对应的图生图模型。同时调整 Composer，让模型选择器位于输入框左上角，并使移动端底部图片选项、预计积分和发送按钮保持一行。

## 2. 已确认决策

- 使用“方案 A”：`selectedModel` 始终代表用户选择的文生图主模型，另行派生实际报价和请求所用模型。
- 模型弹窗只展示文生图主模型，不把 `task === 'image-to-image'` 的映射子模型作为独立选项。
- 模型选择器移动到输入框内部左上角。
- 参考图缩略图区域保持当前位置不变，不随模型选择器移动。
- 上传第一张参考图后，自动使用主模型的 `editModel`；移除最后一张参考图后，自动恢复主模型。
- 主模型没有有效 `editModel` 映射时，隐藏上传按钮并禁止拖放上传。
- 切换至不支持图生图的主模型时，如已有参考图，自动清空并显示一次提示。
- 删除当前异模式模型灰显、禁用、“不支持”徽标、跨模型 fallback 和自动切换 Toast。

## 3. Composer 布局

### 3.1 信息层级

Composer 保持一个输入容器，内部按以下顺序排列：

1. 左上角模型选择器；
2. 现有参考图缩略图区域，位置和交互保持不变；
3. 提示词文本框；
4. 底部单行工具栏。

底部工具栏：

- 左侧保留上传按钮和图片选项；
- 右侧保留预计积分和发送按钮；
- 移动端与桌面端均为一行；
- 使用 `min-w-0`、可截断文字和 `shrink-0` 控制，避免窄屏横向溢出。

模型弹窗继续锚定模型按钮，并保持当前桌面左右两级、移动端上下两级的品牌/模型响应式结构。

## 4. 主模型与实际模型

### 4.1 状态定义

- `primaryModels`：仅包含文生图主模型。
- `selectedModelConfig`：用户当前选中的主模型。
- `activeModelConfig`：报价、能力选项和提交请求实际使用的模型。

派生规则：

```text
无参考图：activeModelConfig = selectedModelConfig
有参考图：activeModelConfig = selectedModelConfig.editModel 对应的模型
```

只有当 `editModel` 非空且能在完整模型目录中找到对应模型时，才视为支持图生图。悬空映射按“不支持”处理，避免报价或请求使用不存在的资源。

### 4.2 纯函数边界

在 `src/lib/utils/image-generation.ts` 中增加并单测以下职责：

- 从完整目录筛出可展示的文生图主模型；
- 解析主模型的有效图生图映射；
- 判断主模型是否支持参考图片；
- 根据参考图是否存在解析实际模型。

组件只负责状态和 UI，不在多个响应式块中重复模型反查规则。

## 5. 模型弹窗

- 品牌分组基于 `primaryModels`，不再基于包含图生图子模型的完整目录。
- 所有展示出来的主模型均可直接选择，不按当前模式灰显。
- 主模型名称后，如果存在有效图生图映射，显示小型图片能力图标。
- 图标使用本地化可访问名称“支持参考图片”，支持键盘用户和辅助技术理解；视觉图标不作为唯一信息来源。
- 模型名称继续左对齐并占据剩余空间；价格和能力标识保留在名称右侧。
- 基础价格按当前是否有参考图显示主模型 `basePrice` 或映射模型的图生图价格。

## 6. 上传与切换行为

### 6.1 支持图生图

- 显示上传按钮和隐藏文件输入。
- 支持按钮选取、拖放和现有文件校验。
- 上传第一张图片后，不改变 `selectedModel` 和用户看到的模型名称；`activeModelConfig` 自动变为映射子模型。
- 保留参考图区域的现有位置、预览、移除和数量裁剪行为。
- 删除最后一张参考图后，`activeModelConfig` 自动恢复主模型。

### 6.2 不支持图生图

- 不渲染上传按钮；文件输入可以保留为不可触发的基础设施，但不得有可操作入口。
- `dragover` 不进入高亮状态，`drop` 不读取或添加文件。
- 用户切换到该模型时若已有参考图：
  1. 清空全部参考图；
  2. 恢复文生图报价与请求；
  3. 显示一次本地化提示“该模型不支持参考图片，已移除上传的图片。”
- 清空发生在显式模型选择处理函数中，不使用被动响应式循环，避免重复 Toast。

### 6.3 切换到另一个支持图生图的模型

- 保留已有参考图；
- 实际模型自动切到新主模型的映射子模型；
- 按映射子模型的 `imageInputMaxCount` 裁剪超量参考图，并沿用现有裁剪提示；
- 自动重新计算报价和能力选项。

## 7. 报价、能力与请求

以下数据统一使用 `activeModelConfig`：

- credits 报价资源 ID；
- 文生图/图生图 action；
- 分辨率、比例、质量、图片数量和步数能力；
- 图生图参考图上限；
- 最终 API payload 的模型 ID。

以下数据继续使用 `selectedModelConfig`：

- 模型触发器名称；
- 模型弹窗选中态；
- 品牌定位；
- 是否展示“支持参考图片”图标和上传入口。

这样可避免“界面显示图生图子模型”或“用户选择被系统偷换”，同时保证报价与实际请求完全一致。

## 8. 可访问性、响应式与 i18n

- 模型按钮、上传按钮和发送按钮保留语义化 `button`、可见焦点和足够触控区域。
- 模型弹窗保留现有 `role="option"`、`aria-selected` 和点击外部关闭行为；移除不再适用的 `disabled`、`aria-disabled` 与 `tabindex=-1`。
- 能力图标提供本地化可访问名称和 Tooltip，不依赖 hover 才能理解。
- 新增英文和简体中文文案：
  - “Supports reference images” / “支持参考图片”；
  - “This model does not support reference images. Uploaded images were removed.” / “该模型不支持参考图片，已移除上传的图片。”
- 至少验证一个移动窄屏和一个桌面视口，检查底部工具栏不换行、模型弹窗边界、参考图区域和深浅色。
